## 前置阶段：确定结构与来源（已完成第一版）

- 建立九个有边界的读取合同，固定六份GXX源码摘要，区分实际调用、注释代码和已知有问题的旧写入函数。
- 新增只读结构检查器与CLI，输出字段布局、逐槽物理/解码后位置、坏块原因、重叠和未知区段；不扫描猜图、不修改原包。
- 五包6000槽结构及独立像素回归通过；这是源码工作区交付，不是新VSIX或客户端验收。
- 规范并非所有历史格式的完整实现。完整UI状态账本、更多布局、统一生产边界检查等仍按下列步骤推进。

## 目标与边界

对已列入兼容清单、数据完整且密码正确的归档，保留全部逻辑槽位、正确解码所有已支持图片、展示真实尺寸/偏移/透明度，并让每一个未能展示的槽位有准确可定位的原因。

“完整”不能定义为不再报错。数量必须可对账、坏图不能伪装空图、未知格式不能猜图、原文件不得被后台重写。游戏内复合效果另以引擎/脚本/数据库合同验收。

## 第 1 步：统一 profile 与错误分类

**输入：** 当前 GOM/GEE/HXM/PACK4 reader、bridge、缓存摘要和错误提示。

**实施：**

- 以签名、全局头、索引不变量选择格式实现；保存 `family/profile/version/decoderRevision`，不把所有 `.pak` 套同一解码器。
- 统一结构化原因：密码确认失败、密码或 profile 不匹配、未知全局头、索引截断、块重叠、不支持像素布局、解压失败、源文件变化、资源限制。
- 保存失败阶段、原逻辑 ID、必要的偏移/长度；不记录密码、密钥或原始敏感解密头。
- GOM 不再把所有错误包装成密码错误；只有有充分验证依据时才用“密码错误”。

**验收：**

- 同一正常包 direct/legacy/Worker 的 profile 一致；缓存重开保持一致。
- 错误密码、未知版本、单图不支持布局、截断分别给出正确原因，不互相冒充。
- 更新解码语义时旧缓存安全失效，不沿用过期 profile；原始包 SHA-256 不变。

## 第 2 步：补齐结构边界与有界解压

**输入：** 本轮 `gom-overlapping-blocks`、`inflate-declared-size` 失败场景，以及既有正常回归。

**实施：**

- 统一验证全局头、索引、每个图头和负载的合法区间。GOM/GEE3 补充相邻块、索引区侵入等检查；已知 profile 的别名索引规则单独定义，不能盲目放开重复偏移。
- 解压前按已确认布局限制最大输出；限制实际输出、压缩流完整消费、尺寸乘法、槽位数量和分配量。
- checksum 恢复只在有明确证据的兼容条件内执行，标记恢复状态，不将恢复等同独立像素验证。
- 正常大文件采用按需读取和有界并发，超过限制给出明确可操作原因。

**验收：**

- 本轮重叠样本不能再把下一图头当像素；可以定位损坏 ID，其他可隔离的合法槽位仍保持原序号。
- 声明16字节但输出1MiB的压缩块在有界解压阶段拒绝，不先产生完整异常输出。
- 截断、负载跨界、重复索引、压缩尾部、多余/不足输出、溢出均有负向测试。
- 正常五包6000槽的 PNG、偏移与空槽基线不变。

## 第 3 步：建立逐槽状态账本

**输入：** parser 已知道的原始槽位与错误信息，不只传出有效 blocks。

**实施：**

- 每槽记录 `empty / indexed-unverified / decoded / recovered / unsupported / corrupt`。
- 保留原始 ID；有记录但完全透明的图仍为 decoded，不转为空槽。
- direct/legacy/Worker/缓存重开共享同一状态语义；未完成的解码不假报成功。
- 缺块处理区分真正零索引与损坏/不支持。缺图警示仅影响对应槽位，不在游戏预览中错位补下一张图。

**验收：**

- 本轮 ID1260 显示损坏；ID1655 显示空槽，两者不再混淆。
- `总槽位 = 空槽 + 待验证 + 正常 + 恢复 + 不支持 + 损坏`，各状态互斥，可导出脱敏清单。
- 有一张坏图时其后 ID、动画帧范围、引用全部不移位。
- 新旧缓存迁移失败时可重新建立，不清空用户其他归档缓存。

## 第 4 步：补有源码依据的 HXM/Lz 布局

**输入：** GXX 特定版本源码、独立像素向量；同时补收对应真实样本和可信参考输出。

**实施顺序：**

1. 校准 bfType 单字节与保留字节边界。保留原字段；未确认的保留位不猜含义。
2. 普通独立alpha补齐8/16/24/32位、奇数宽多行测试。**2026-09-26校正：活动源码pf15bit实际走565，不能按枚举名实现555；该分支须先补实样与可信参考。**
3. 独立实现 Lz V0：8字节 offset/length 索引、12字节图头、全局色深及 raw/zlib/RLE 分支。
4. 专门验证 SD 4-bit alpha：奇数宽、高低半字节、行序、透明边缘和混合。GXX 源码存在可疑的长度参数调用，不能照搬后自称正确。

2026-09-26已完成第1项、普通alpha测试和第3项的确定布局，另校准HXM特有的565左移转换。非对齐多行RLE涉及原源码的紧密输出/对齐拷贝矛盾，暂不开放；不是把失败当空图。第4步的实样与客户端验收尚未闭环。

**验收：**

- 每个新增布局分别通过独立期望 RGBA、负偏移、首中尾空槽、错误密码、截断、direct/legacy/Worker/重开测试。
- 对真实样本逐槽核对图数、尺寸、偏移、RGBA 与可信参考；没有实样的条目保持“代码实现/合成验证，真实兼容待验”。
- 特殊 alpha 的半透明边缘必须在多种背景上视觉核对，不能只看能否输出 PNG。
- 不将这些行为自动套用 GOM/GEE。

## 第 5 步：按证据扩展 PACK4 与其他历史 profile

**输入：** 不受支持的真实文件；最好包含同一问题包经 GM 同格式转换后的配对文件，或可信 writer/source。

**实施：**

- PACK4 新 type、压缩图、不同尾索引/混淆方式分别注册；保留已通过的标准与 KSF 分支。
- 空 KSF 分支、GEE legacy 非零 X/Y、GEEM2 独立建样本条目。
- 密码正确但 profile 未知时输出脱敏结构诊断，不用全文件找 zlib 或试出一张图就宣布兼容。
- 未引用区域可以记录为未知原始区段，不能自动当新图片追加或重新编号。

**验收：**

- 新旧每个 profile 同时回归；身份识别不会使另一格式误匹配。
- 每个新增分支至少有独立布局依据和对应实样，记录实际覆盖的类型，而不宣称整个引擎所有历史版本均支持。
- 原/转换后文件对照核验逻辑 ID、空槽、X/Y、alpha、像素；转换若跳过图片不得叫无损。
- 缺必要样本时保持精确待验清单，不通过放宽校验隐藏问题。

## 第 6 步：提供全量验证与可控诊断

**输入：** 逐槽账本、现有 Worker 池和按需读取接口。

**实施：**

- 保留快速建立索引作为正常打开方式；另外提供可取消、可恢复的“验证全部图片”。
- 验证可流式完成，无须把全部 PNG 常驻内存或全部导出到磁盘。
- 缓存验证状态关联源文件指纹、profile 和解码器版本；源文件变化后旧结果不能继续显示为已验证。
- 输出简明汇总与失败 ID 清单；详细解释按需展开。

**验收：**

- “已索引”与“全部验证通过”两个状态不混用。
- 取消不会标记成功，恢复不漏槽、不重复计数；单张失败不会终止后续所有可读图的诊断。
- 测量首屏、全量耗时、峰值内存、缓存大小和取消响应；指标附样本尺寸/硬件，不用局部解密微基准代替整包性能。
- 原始包在验证前后内容不变。

## 第 7 步：完善展示，而非增加解释文字

2026-09-26第一批实现见[素材只读查看器报告](PAK_ASSET_INSPECTION_20260926.md)；实时状态、动画和进度条后续增量见[本轮汇总](PAK_COMPLETION_20260926.md)。

**输入：** 统一图片数据、逐槽状态、现有素材虚拟列表及画布消费者。

**实施：**

- 列表简洁显示 ID 与状态；总数分开显示槽位/有图/空槽/失败。
- 选中后提供可折叠详情：profile、尺寸、原始 X/Y、色深/alpha、压缩信息、具体错误。
- 增加原始像素模式和按偏移定位模式；透明棋盘/黑/白背景、原点十字、像素级缩放。
- 动画明确帧起点/数量/间隔/方向；区分普通 alpha 与指定混合预览。外部参数来源可追溯，不把猜测当包内信息。
- Ctrl+F12、ITEMSHOW、地图等继续遵守各自引擎与语句的坐标规则，不统一强加一种偏移策略。

**验收：**

- 真实 VS Code Webview 中能滚动到所有槽位、按 ID 定位、查看错误、重新验证；大包不冻结主界面。
- 原点和负偏移准确，透明/半透明无错误黑边；同一锚点动画不因每帧自动居中而抖动。
- 空帧与坏帧有区分，帧序不补位；数据查看与脚本最终绘制分别检查。
- 与明确版本的参考工具/客户端比较，记录普通像素差异与客户端混合差异，不仅比较截图观感。

## 第 8 步：形成发布级兼容矩阵

**输入：** 各 profile 的真实样本、独立像素基线、异常夹具及前七步的结果。

**验收清单：**

- 覆盖不以文件名/引擎名计，而以 `family × version × type/flags × compression × password encoding` 计。
- 同时验证图数、空槽位置、尺寸、X/Y、行序、RGBA、缓存重开、Worker一致性、源文件不变。
- 中文/尾部空格/空密码按确切字节合同测试；真实密码不进源码、日志或安装包。
- 最终 VSIX 解包运行时再测相同语料，并单独完成真实 VS Code 和必要的客户端验收。
- 发布说明明确“已实现、合成验证、实样验证、客户端验收、尚待样本”五种证据，不以一个“兼容”勾选替代。

## 自动兼容转换的边界

正常读取优先采用**内存/缓存中的统一索引与 RGBA 视图**，不是重写用户 PAK。KSF 当前保存解码后的短像素前缀已体现这种思路。

只有另获写入/导出任务、原格式完整读取且转换语义有依据时，才考虑单独导出转换副本：保留原文件，写临时候选，独立回读，比对逻辑 ID、空槽、坐标与像素后发布。未知字段无法保真时拒绝“无损”声明。

转换无法补回被截断的数据，也不能保证恢复所有未知 profile。用户可用的结果应是：**可读的完整展示；不可读的精确定位；从不悄悄丢图或改号。**
