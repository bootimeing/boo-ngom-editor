# ToolKnit 工具复现与 BOO 扩展集成评估报告

调研日期：2026-08-07  
目标产品：BOO UI 编辑器 VS Code 扩展 V4.3.0  
调研范围：ToolKnit 当前工具目录、公开源码、桌面端源码、许可证、构建结果，以及与 BOO 现有功能和低配置用户场景的适配性。

## 1. 结论先行

ToolKnit 当前首页列出 92 个入口，实际由 91 个独立工具和 1 个世界节日表组成。它的主要价值不是某个独占算法，而是把 Canvas、Web Audio、FFmpeg、PDF、文本处理等能力做成了本地运行的小工具。

BOO 不适合把这 92 个工具全部搬入扩展。全部加入会让产品定位变散、维护面扩大、扩展详情页和运行时负担增加。建议只建设一个“资源工具箱”入口，第一批围绕传奇素材与脚本时间处理实现以下 8 项：

| 优先级 | 工具 | BOO 价值 | 建议结论 |
|---|---|---|---|
| P0 | 图片裁剪 | UI、物品、怪物、地图标识素材整理 | 直接实现 |
| P0 | 异形裁剪 | 圆形头像、透明素材、多边形和自由轮廓 | BOO 自主扩展实现 |
| P0 | 翻转与旋转图片 | 修正素材朝向、镜像和批量加工 | 直接实现 |
| P0 | GIF 转 PNG 序列图 | 将动画素材转成可用于补丁的逐帧图片 | 直接实现；ToolKnit 当前没有该工具 |
| P0 | MP3 转 WAV | 把音效和语音转换为客户端常用 PCM WAV | 直接实现 |
| P0 | 时间戳转换 | 脚本活动时间、日志时间和接口时间互转 | 直接实现 |
| P0 | 中国节日表 | GM 活动排期、法定假期与传统节日查询 | 自建权威离线数据 |
| P1 | MP4 转 GIF | 宣传图、教程和素材预览 | 可实现，但最后实施 |

推荐顺序不是照着网页逐项复制，而是先交付低风险、低内存的图片与时间工具，再做 GIF、音频，最后处理视频。这样能较早获得实际价值，也不会让第一版被 FFmpeg、视频编码兼容和大内存问题拖住。

## 2. 复现与许可证边界

### 2.1 可以做什么

- 根据公开的功能表现，自主设计 BOO 的界面和处理流程。
- 使用浏览器标准 API，例如 Canvas、Web Audio、Web Worker 和 File API。
- 使用许可证明确兼容的第三方库，并保留许可证和修改说明。
- 参考 ToolKnit Desktop 的处理思路。该仓库采用 Apache-2.0，可按许可证要求复用部分核心模块。

### 2.2 不能直接做什么

- ToolKnit 网站条款明确把网站设计和网站代码作为专有内容，不能直接抓取页面源码后打包进 BOO。
- 网站仓库虽然带有 MIT 文件，但仓库说明又明确表示主站源码并未开源。不能只看到仓库许可证就把整个网站当成可复制代码。
- ToolKnit 品牌、Logo、页面排版和文案不属于 BOO，应使用 BOO 自己的名称和视觉系统。
- 背景移除示例依赖 `@imgly/background-removal`。该库为 AGPL-3.0，不能在未完成合规评估或购买商业许可证的情况下静默并入 BOO 的 MIT 发布包。

## 3. 八项优先工具的详细方案

### 3.1 图片裁剪

**目标能力**

- 支持 PNG、JPG、WebP、BMP；GIF 只按静态首帧进入普通裁剪。
- 自由裁剪，以及 1:1、4:3、16:9 等比例锁定。
- 支持鼠标拖动选区，也支持整数 `X/Y/宽/高` 精确输入。
- 按源图实际像素导出，不按预览缩放后的尺寸导出。
- PNG 保留透明通道；JPG 可选择背景色和质量。
- 默认不覆盖原文件，输出名为 `原名_crop.png`。

**实现方式**

用 Canvas 或 OffscreenCanvas 完成解码、选区预览和导出。预览画布只负责交互，导出画布按原图分辨率重绘。扩展宿主负责选择文件、选择输出目录和原子写入，Webview 不直接访问任意磁盘路径。

**需要特别测试**

- 透明 PNG、超长图、1 像素边界、带 EXIF 方向的手机 JPG。
- 裁剪框超出图片、宽高为 0、文件损坏和内存不足。
- 预览缩放后导出像素仍与源图坐标完全一致。

### 3.2 异形裁剪

ToolKnit 只提供圆形裁剪，用户提出的“异形裁剪”应作为 BOO 的增强能力独立设计。

**第一版形状**

- 圆形、椭圆、圆角矩形。
- 多边形点选，双击闭合。
- 自由画笔轮廓，松开后闭合并生成蒙版。
- 反选、羽化 0-10 像素、清除重画。

**输出规则**

- 固定导出透明 PNG，因为 JPG 不能保留异形外部透明区域。
- 输出画布默认裁到蒙版包围盒，也可选择“保持原图尺寸”。
- 多边形和自由轮廓必须保存最后一个编辑状态，撤销只撤销轮廓点，不修改原图。

**实现方式**

使用 `Path2D` 或灰度 Alpha 蒙版，通过 `destination-in` 合成。该功能不需要 AI 模型，也不需要引入 AGPL 背景移除库。

### 3.3 翻转与旋转图片

**目标能力**

- 水平翻转、垂直翻转、左转 90 度、右转 90 度、旋转 180 度。
- 操作可连续叠加，支持撤销、重做和恢复原图。
- 旋转 90/270 度时自动交换画布宽高。
- 保留 PNG Alpha；JPG 可设置背景与质量。
- 第一版支持单图，第二版再支持批量文件和整目录。

**实现方式**

Canvas `translate/scale/rotate/drawImage` 即可，不需要第三方依赖。内部保存变换矩阵，不在每次点击时反复编码图片，只有导出时编码一次，避免累积画质损失。

### 3.4 GIF 转 PNG 序列图

这是 ToolKnit 当前目录中没有、但对传奇素材工作流很有价值的功能。

**目标能力**

- 读取 GIF 的逻辑画布、每帧补丁、透明色、延迟和 disposal 规则。
- 导出的是合成后的完整帧，不是尺寸可能很小的局部差分帧。
- 不过滤透明帧或重复帧，避免破坏原动画节奏和图片序号。
- 默认输出 `000001.png`、`000002.png`，并允许从 0 或 1 开始编号。
- 可选输出 `frames.json`，记录每帧延迟、循环次数和源尺寸。
- 选择输出目录后逐帧写入，支持取消和进度提示。

**推荐依赖**

使用 MIT 的 `gifuct-js` 解析帧。实现时必须正确处理 disposal 0/1/2/3：

- 0/1：保留前一帧画布。
- 2：显示后恢复该帧区域到背景。
- 3：显示后恢复到绘制该帧之前的画布。

只把 `decompressFrames()` 返回的 patch 直接保存会得到错位或缺块图片，这是该功能最容易出现的错误。

**低配置优化**

- 使用 Worker 解码，主界面只显示缩略预览和进度。
- 每合成一帧就编码、发送、写盘并释放，不把全部 PNG Blob 留在内存中。
- 开始前显示预计内存：`宽 × 高 × 4 × 同时保留帧数`。
- 大图或超多帧自动关闭全帧缩略图，只显示当前帧和前后少量帧。

### 3.5 MP4 转 GIF

**为什么后置**

视频解码、随机定位、缩放、调色板和 GIF 编码都很耗 CPU。不同 Electron/VS Code 版本对 H.264、HEVC、AV1 等编码支持也不同。若直接捆绑完整 FFmpeg，VSIX 可能增加数十 MB，并带来 DLL、许可证、更新和安全扫描成本。

**第一阶段：轻量本地路径**

- 通过 `<video>` 解码当前 Chromium 能播放的 MP4。
- 让用户选择起止时间、5/10/15/20 FPS、320/480/640/原始宽度。
- Canvas 抽帧，Worker 中用 MIT 的 `gifenc` 量化和编码。
- 默认建议 10 FPS、480 像素宽、最长 15 秒；允许提高，但显示预计帧数和内存警告。
- 导出前生成 3-5 秒低分辨率预览，确认裁剪范围和速度。

**第二阶段：可选 FFmpeg 后端**

- 仅在浏览器解码不支持或用户选择高质量模式时启用。
- 不默认塞入 VSIX；优先允许用户选择本机 `ffmpeg.exe`。
- 如将来做按需下载，必须固定来源、版本、SHA-256、许可证，并存放在扩展 `globalStorage`，不能静默执行不明二进制。
- 编码使用 `palettegen + paletteuse`，比直接 GIF 量化有更稳定的色彩质量。

**失败提示必须明确**

应区分“容器是 MP4 但视频编码不支持”“视频损坏”“无视频轨”“内存不足”“用户取消”，不能统一提示为转换失败。

### 3.6 MP3 转 WAV

**目标能力**

- 输入 MP3，输出标准 RIFF/WAVE PCM16。
- 可选 22050、44100、48000 Hz。
- 可选单声道或保持双声道。
- 显示时长、源采样率、声道数、输出预计大小。
- 第一版单文件，第二版批量目录。

**实现方式**

使用 Web Audio API 的 `decodeAudioData` 解码，必要时用 `OfflineAudioContext` 重采样，再由 Worker 按小端序封装 PCM16 WAV。只做 MP3 到 WAV 时无需引入 FFmpeg。

**准确性边界**

WAV 是无压缩输出，但不能恢复 MP3 编码前已经丢失的音质。界面应写“转换为 PCM WAV”，不要宣传为音质修复或真正无损还原。

### 3.7 时间戳转换

**目标能力**

- Unix 秒、Unix 毫秒、北京时间、UTC 和 ISO 8601 双向转换。
- 自动识别 10 位秒和 13 位毫秒，但允许手动覆盖单位。
- 显示当前时间并可一键复制。
- 支持负时间戳、2038 年以后日期、闰年和不同时区。
- 为脚本使用提供 `YYYY-MM-DD HH:mm:ss` 和纯数字格式。

**实现方式**

完全使用 JavaScript `Date` 和 `Intl.DateTimeFormat`，无第三方依赖。内部只使用毫秒整数，输入解析后立即校验是否为有限数值，禁止依赖浏览器对含糊日期字符串的自动猜测。

### 3.8 中国节日表

该功能必须拆成两层，否则会把“传统节日”和“法定放假调休”混为一谈。

**传统节日层**

- 春节、元宵、清明、端午、七夕、中秋、重阳等。
- 可使用 MIT 的农历库计算公历日期，并通过固定测试样例校验。
- 可扩展二十四节气和 GM 自定义活动日。

**法定安排层**

- 每年依据国务院办公厅正式通知录入放假区间和调休上班日。
- 数据包含 `date`、`name`、`kind=holiday/workday`、`sourceUrl`、`publishedAt`、`verifiedAt`。
- 官方尚未发布下一年度安排时，明确显示“尚未发布”，不能根据往年规律推算成官方结果。
- ToolKnit 的中国页面适合快速参考，但数据条目不足以替代中国官方调休表。

**面向 GM 的增强**

- 按月列表和日历视图。
- 复制日期、导出 CSV。
- 根据开始/结束日期生成活动排期草稿；生成内容仍由用户确认，不直接修改服务端脚本。

官方数据入口应记录到版本化 JSON。以 2026 年为例，应引用[国务院办公厅关于 2026 年部分节假日安排的通知](https://www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm)，而不是只复制第三方节日列表。

## 4. BOO 内的产品形态

### 4.1 入口

不新增 Activity Bar 图标。建议在现有“BOO 脚本助手 > 快捷工具”中增加一个“资源工具箱”按钮，打开编辑区 Webview。工具箱顶部用标签或分段控件切换：

1. 图片处理
2. GIF 拆帧
3. 视频转 GIF
4. 音频转换
5. 时间与节日

图片裁剪、异形裁剪、翻转和旋转应共用同一张预览画布与同一个文件，不做四个割裂页面。

### 4.2 建议文件边界

```text
src/providers/resource-toolbox.ts
src/utils/media/image-transform.ts
src/utils/media/gif-sequence.ts
src/utils/media/audio-wav.ts
src/utils/media/video-gif.ts
src/utils/time-converter.ts
src/utils/china-holidays.ts
media/resource-toolbox.html
media/resource-tools/
data/china-holidays/
tests/resource-toolbox-*.test.js
```

不要继续把大段功能塞进 `src/assistant.ts`。Provider 只负责面板、消息协议、文件选择和生命周期；处理逻辑放入可单测模块；重任务放 Worker。

### 4.3 文件处理协议

1. 扩展宿主通过 VS Code 文件选择器取得本地 URI。
2. 宿主只把必要的文件数据或受控 Webview URI 发给页面。
3. 页面或 Worker 本地处理，持续回报百分比、当前帧和可取消状态。
4. 用户选择输出目录，宿主写入临时文件。
5. 单个文件写完后原子改名，取消或失败时清理临时文件。
6. 原文件默认永不覆盖；用户明确确认后才允许覆盖。

### 4.4 与现有素材系统的关系

第一版只处理用户主动选择的普通媒体文件，不直接修改 PAK/JPK/WIL/WZL。后续可从 UI 编辑器或数据库素材预览增加“发送到资源工具箱”，但输出仍是新 PNG/WAV/GIF 文件，由用户确认后再导入补丁。

这样可以避免工具箱绕过现有素材索引、图片序号和缓存规则，也不会误改补丁文件。

## 5. 低配置电脑专项设计

| 风险 | 处理要求 |
|---|---|
| 打开工具箱即占内存 | 所有解码器按标签首次使用再动态加载 |
| GIF 全帧驻留 | 流式合成、逐帧写盘、限制缩略图数量 |
| MP4 转 GIF 卡住界面 | Worker 编码、可取消、进度和阶段说明 |
| 大文件导致扩展宿主崩溃 | 开始前估算内存；超阈值提示降分辨率/FPS/时长 |
| Blob/Object URL 泄漏 | 切换文件、关闭面板和导出后统一 `revokeObjectURL` |
| 多任务并行抢内存 | 默认一次只运行一个媒体任务，排队而非并发 |
| VSIX 继续膨胀 | 不默认捆绑 FFmpeg、AI 模型或远程 CDN 资源 |
| 重复转换耗时 | 同一会话内缓存解码后的源信息，不跨会话缓存巨型帧数据 |

建议软限制：

- 普通图片解码后像素内存超过 512 MB 时警告。
- GIF 预计总未压缩像素超过 1 GB 时启用低内存模式。
- MP4 默认最长 15 秒、480 宽、10 FPS；高配置选项由用户主动提高。
- MP3 解码预计 PCM 超过 512 MB 时提示分段或使用可选 FFmpeg 流式后端。

这些值是初始保护线，最终应根据三档测试机实测调整，不能当成已验证的固定上限。

## 6. 安全与发布要求

- 使用现有 `src/utils/webview-security.ts` 生成 CSP 和 nonce。
- Webview 不加载 CDN 脚本、远程字体或远程 Worker。
- 处理文件名时剥离路径穿越字符，序列帧文件名由程序生成。
- 所有第三方库锁定精确版本并进入依赖清单与 Third-Party Notices。
- Apache-2.0 代码保留版权、许可证、NOTICE 和修改说明。
- 不引入 AGPL 模块，除非未来产品整体合规方案经过单独确认。
- 不执行用户文件中携带的脚本或元数据。
- MP4、GIF、MP3 等解析器都要把损坏输入当成不可信数据处理。

调研时对 ToolKnit Desktop 的当前前端执行了 `npm ci` 和 `npm run build`，构建可通过；但依赖审计发现其当时锁定的 `pdfjs-dist 6.0.227` 落在 [GHSA-hq66-cqwq-w95j](https://github.com/advisories/GHSA-hq66-cqwq-w95j) 影响范围内。BOO 即使未来加入 PDF 工具，也不能原样复制该版本，应先升级并关闭不需要的 PDF 脚本能力。

## 8. 验收标准

### 8.1 功能准确性

- 图片工具输出尺寸、Alpha 和坐标与金样图逐像素比较。
- GIF 使用 disposal 0/1/2/3、局部帧、透明帧、重复帧样本回归。
- MP4 对恒定帧率、可变帧率、旋转元数据和不支持编码分别测试。
- WAV 校验 RIFF 长度、PCM16、采样率、声道和时长。
- 时间戳覆盖秒/毫秒、UTC+8、闰日、负值和 2038 年以后。
- 每条法定调休数据都能追溯到官方来源；未发布年份不伪造。

### 8.2 性能与体验

- 转换期间编辑器可继续输入和切换文件。
- 取消后 2 秒内停止产生新输出，并清理临时文件。
- 连续打开关闭工具箱 20 次，内存不持续线性增长。
- 完成大任务后，帧缓存和 Object URL 可被回收。
- 未使用视频工具时，不加载视频编码器，也不增加常驻内存。

### 8.3 发布完整性

- `npm run compile`、相关单测和 Webview 安全测试通过。
- 解包 VSIX 核对依赖、Worker、许可证和资源路径。
- 对比加入前后的 VSIX 大小、激活耗时与扩展宿主峰值内存。

## 10. 开源与构建核验记录

本次不是只看网页名称，还做了以下验证：

- ToolKnit 首页当前显示 92 个入口，并给出 PDF 5、图片 18、视频 4、音频 6、文本 11、计算 7、时间 6、创意 28、AI 4、自测 2 的分类计数。
- ToolKnit Desktop 当前仓库版本为 V1.3.0、Apache-2.0，公开了 PDF、图片、音视频等核心模块。
- 在隔离目录执行其 `npm ci` 成功，`npm run build` 成功；构建产物包含数百 KB 到 2 MB 以上的大块 PDF/字体/Excel 模块，说明不能整包照搬进 BOO。
- `npm run test:release` 的 PDF、AI、文本、密码、颜色、图片核心测试通过到音频阶段；音频运行时因测试机没有 FFmpeg 而停止，所以不能表述为“全部发布测试通过”。
- `npm audit` 当时报告 1 个高危项，即受影响的 `pdfjs-dist` 版本。BOO 当前优先的 8 项不需要 PDF.js。
- ToolKnit Web 仓库只公开了少量独立演示；网站主体不是公开可复用源码。

## 11. 最终建议

1. 先批准一个“资源工具箱”产品入口，不逐个增加侧栏图标。
2. 第一批一次性交付图片裁剪、异形裁剪、翻转旋转，并共用预览画布。
3. 随后交付 GIF 转 PNG 序列、MP3 转 WAV、时间戳和中国节日表。
4. MP4 转 GIF 单独做性能验证版，默认不捆绑 FFmpeg。
5. 暂不引入 PDF、AI 背景移除、娱乐、自测和通用办公工具。
6. 在任何实现开始前，为 V4.3.0 做可回滚备份；新功能使用独立模块，不扩大 `assistant.ts`。
