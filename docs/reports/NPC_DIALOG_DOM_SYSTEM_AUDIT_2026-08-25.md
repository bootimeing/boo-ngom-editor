# Ctrl+F12 NPC 脚本可视化面板完整任务报告

日期：2026-08-25  
项目：BOO 可视化编辑器（VS Code 插件版）  
当前版本：4.3.3（本任务未要求升级版本或打包）

## 1. 任务边界

本次验收对象不是原有 `media/editor.html` UI 编辑器，而是通过 `Ctrl+F12` 从当前 `[@函数]` 打开的独立 NPC 脚本可视化面板。检查范围覆盖完整链路：

1. 当前函数与关联 `GOTO/@标签` 的源码读取。
2. `#SAY/#ELSESAY`、多个条件组和默认界面的场景组合。
3. 脚本变量、数据库字段、配置表、列表和公式的静态求值。
4. GOM、翎风、996PC 三套界面语句目录到 DOM 控件的转换。
5. PAK/JPK/WIL/WZL 缓存素材、物品数据库 Looks 与界面资源的关联。
6. DOM 绘制、素材层级、动画、按钮状态、容器嵌套和传统流式文字。
7. 鼠标拖动、方向键微调、属性输入、撤销、重做、条件切换和缩放。
8. DOM 坐标反算为源码坐标、精确文本替换、应用、保存和冲突保护。
9. Webview 生命周期、浮动窗口兼容、性能、安全及旧编辑器隔离。

## 2. 最终数据流

```text
当前 TXT + 光标所在 [@函数]
  -> 关联函数与条件块扫描
  -> 变量/数据库/配置/表格静态求值
  -> 引擎独立界面语句目录
  -> 场景模型 + 控件参数 + 局部/绝对坐标
  -> 缓存素材与物品 Looks 解析
  -> 独立 Webview DOM
  -> 拖动/键盘/属性输入形成局部草稿
  -> 父容器坐标反算 + M2 修正逆运算 + 旧控件 4px 偏差逆运算
  -> 仅替换原 TXT 中对应 X/Y 数字
```

## 3. 已完成实现

### 3.1 条件、页面和变量

- 默认 `#SAY` 会与当前满足的条件界面共同显示。
- 每个条件组可独立选择“满足/不满足”，多个满足条件可以同时进入一个页面。
- 同一 `[@函数]` 内重复出现的同一条件会合并为一个切换项；每个原始条件块仍保留并同时响应该切换。
- `#ELSESAY` 在条件不满足时正常显示，恢复默认预览后会重新选择所有不满足分支。
- 条件切换只重建预览模型，不写入 TXT，并保留兼容的坐标草稿。
- `GOTO`、链接标签及关联取值函数会参与变量求值。
- 可确定的数值、字符串、嵌套变量、数据库字段、INI、CSV/XLS、列表和公式显示实际值。
- 无法静态确定的数值使用 `0`，字符串使用空值，并在变量列表中标记为默认值。
- 由变量展开生成的界面控件可预览，但保持源码锁定，避免错误修改变量赋值内部文本。

### 3.2 ITEMSHOW 与物品类控件

- GOM `ITEMSHOW` 已按帮助修正为 11 个参数：物品 IDX、数量、X、Y、背景框、灰化、对齐、宽度、称号模式、Items/StdItem、物品特效。
- 翎风 `ITEMSHOW` 已按帮助修正为 8 个主体参数及单击标签：物品 IDX、数量、X、Y、背景框、发光、灰化、数量单位、标签。
- GOM/996PC 背景框参数为 `1` 时读取 `NewopUI/47`；翎风读取 `NewopUI/250`；大于 `1` 时直接读取指定 NewopUI 序号；`0` 时不绘制框。
- 物品内容通过数据库 `IDX -> Looks` 解析，并沿用 `Items、Items1...Items9` 与 0-99999 Looks 规则。
- 背景框在下层，物品内容在上层；数量单独叠加显示。
- 支持 `UserItem`、`HeroUserItem`、996PC `EquipShow/HEROEquipShow` 的运行时装备框预览。
- 支持 `MakeIndexItem/DBItemShow/HERODBItemShow` 的唯一物品占位预览。
- 支持旧版和 996PC 新版 `ITEMBOX`，使用脚本声明的 WIL/WZL 与背景图片。
- 支持 `CustomItem/HeroCustomItem` 的自定义装备框底图。
- 支持 `StateItem`、`DnItems`、`NewopUI` 的专用资源读取。
- 支持 996PC `BAGITEMS/HEROBAGITEMS/EQUIPITEMS/HEROEQUIPITEMS` 格子列表结构预览。

### 3.3 进度条、动画和按钮状态

- 旧 `PROGRESSBAR` 第 10 个参数已由错误的“模式”修正为“最小值”。
- 支持旧 `PROGRESSBAR` 和 996PC `LoadingBar` 的底图、进度图、偏移、方向、比例及文字预览。
- 支持 `PLAYIMG/PLAYIMGEX/Frames/Effect` 连续帧播放、播放间隔和有限循环次数。
- `Effect` 使用 `num` 作为图片帧数、`count` 作为循环次数，不再混淆。
- 支持 `IMGEX` 和 996PC `Button` 的默认、悬停、按下三态素材。
- 动画最多载入前 240 帧，防止异常脚本造成 Webview 资源膨胀；超过上限会显示兼容性提示。

### 3.4 容器和传统文字

- 支持 GOM/翎风 `#父容器~#元素`、`~#根容器` 和 `#父容器~` 语法。
- 支持 996PC `id` 与 `children={...}` 父子关系。
- 模型同时保存源码局部坐标与画布绝对坐标；移动父容器时所有后代控件同步移动。
- 保存子控件时会减去父容器当前位置，再写回局部坐标；父容器与子控件同时修改也能正确反算。
- 检测重复容器 ID、找不到父容器和循环父子关系，并停止不安全的嵌套写回。
- `Layout`、`ListView`、`NewLine` 可视化；旧 ListView 可读取滚动条 WIL 与背景图片。
- 传统非坐标文字保留空格宽度；单个反斜杠 `\` 换到下一视觉行；`&#x20;` 按空格计算。
- 空文字不再回退显示 `<&TEXT` 命令名；`MText` 与位置文字内的 `|` 可按多行正文显示。
- 未收录 `<...>` 语句只生成一个锁定占位，不再同时作为普通文字重复绘制；原文始终保留。

### 3.5 鼠标悬停备注

- 旧式 `TEXT` 会把 `|` 左侧作为画布正文、右侧作为悬停备注，不再把备注直接画进正文。
- GOM `IMG/IMGEX/PLAYIMG` 支持普通文字备注、`^` 换行、`颜色号#文字`、`{文字|颜色}` 和 `ItemShow#IDX#模式`。
- 翎风兼容 `IMG` 的竖线备注、`PLAYIMG/PLAYIMGEX` 的独立备注参数，以及 `CustomItem/HeroCustomItem/StateItem/DnItems/ITEMBOX` 的提示字段。
- 996PC 新界面 `Text/RText/Button/ITEMBOX` 支持 `tips/tipsx/tipsy`；`showtips` 仍按物品属性开关处理，不会误当文字备注。
- 传统 `<显示文字|备注/@标签>` 也能生成流式文字及独立备注，不再落入未知语句或把备注当正文。
- Webview 使用自绘悬浮层和安全的 `textContent`/文本节点，支持彩色分段、换行、鼠标偏移、视口边缘避让，并与 IMGEX/Button 三态素材并存。
- `ItemShow#IDX#模式` 当前显示明确的物品 IDX 与模式提示；不伪造客户端完整物品属性窗口。

### 3.6 坐标和源码安全

- 带 `&` 的绝对坐标不叠加 `NpcMemoOffSetX/Y`。
- 不带 `&` 的相对坐标按 GOM `Mir200\!Setup.txt` 修正值显示。
- 翎风可手工保存工作区内的修正值，并显示登陆器配置中的查找路径提示。
- `TEXT/COUNTDOWN/INPUTTEXT/INPUTNUM` 的历史 4px 源码偏差在显示时减去、保存时加回。
- `ITEMSHOW/IMG/PLAYIMG` 等图像类控件不套用 4px 补偿；`ITEMSHOW` 的画布坐标与源码 X/Y 保持一致。
- 所有写回坐标取整数，拒绝 NaN、无限值和超大数值。
- 保存前核对文档版本和每个数字的原始字符；源码已变化时拒绝覆盖。
- 只替换 X/Y 数字跨度，不重排空格、参数、大小写、编码、注释或未知语句。
- 重新载入或修改翎风修正值前，如存在草稿会要求确认；引擎切换会尽量保留仍兼容的草稿。

### 3.7 生命周期、性能和隔离

- Webview 消息监听现在先注册，再写入 HTML，消除了首次 `ready` 丢失的竞争窗口。
- 条件重载带修订号，较慢的旧异步结果不会覆盖最新场景。
- 拖动过程中只在“干净/已修改”状态改变时通知扩展宿主，不再每个 `mousemove` 发送消息。
- 同一资源包的动画帧只定位一次缓存包、只读取一次素材表，避免每帧重复扫描全部缓存。
- 动画在场景重绘时清理计时器，防止隐藏页面持续播放或计时器泄漏。
- 所有脚本文字、变量、参数和诊断通过 `textContent` 写入 DOM。
- Webview 继续使用项目统一 CSP/nonce 和受控资源根。
- 原 UI 编辑器 `media/editor.html` 未改动，SHA-256 仍为：
  `606CFA148B63D691239572FDFBD669D45FA58687BD04C7E0597ED8BCDAC89743`。

## 5. 本次发现并修复的隐性问题

1. 浏览器实际加载时发现一处 `elementVisualSize` 链式调用语法错误，单元测试无法发现，现已由真实 Edge DOM 测试永久覆盖。
2. 未知界面语句会同时进入锁定列表和普通文字布局，造成重复显示，现已改为单个锁定 DOM 节点。
3. 容器前缀会使后续所有参数错位，现已识别前缀并保持参数跨度准确。
4. 父容器移动后，子元素视觉位置和源码局部坐标原先可能脱节，现已统一为局部草稿模型。
5. 996PC `children={...}` 在参数栏会被截成空值，现保留完整花括号内容。
6. `Effect` 的图片数量与循环次数曾可能混用，现分别使用 `num` 和 `count`。
7. 动画逐帧重复扫描缓存与素材表，现改为单次包定位和素材表复用。
8. 每次鼠标移动都向扩展宿主发送 dirty 消息，现只在布尔状态改变时发送。
9. Webview HTML 先设置、消息监听后注册存在首次握手竞争，现已调整顺序。
10. 重载、翎风偏移修改和引擎切换可能静默丢失草稿，现已增加确认或草稿保留。
11. 同一函数内重复的等价条件曾显示多个选项，现已建立原始 ID 到规范 ID 的映射，合并选项但不丢失任何分支界面。
12. 空文字曾因 DOM 的布尔回退而显示 `<&TEXT` token，现已改为保留空值；同时补齐 `MText` 多行正文参数识别。
13. `ITEMSHOW` 坐标现已有独立的零补偿和精确回写回归测试，不再依赖“图像类应该没问题”的隐式假设。
14. 位置 `TEXT` 的 `|` 曾被统一当成多行正文，导致悬停备注直接显示在界面中；现仅 `MText` 把竖线作为正文分行，其他已确认控件拆成正文与备注。
15. 996PC `tips` 曾可能被目录推断成控件正文；现 `text/title` 与 `tips` 使用独立字段，OK 框不再拿备注覆盖控件名称。
16. 备注颜色原先使用近似色，现常用 249-255 严格沿用项目 256 色表，其中 250 为绿色、254 为青色。

## 6. 当前无法做到完全等同游戏客户端的部分

这些限制已通过占位、锁定或提示处理，不会错误改写源码：

1. 玩家当前装备、英雄装备、唯一物品 MakeIndex、背包选择状态等运行时数据，离线时没有唯一真实值，只能显示框、格子和运行时说明。
2. 依赖在线角色、随机数、时间、服务端插件、外部 DLL、网络结果或无限循环的变量，无法保证静态求值；当前使用 0/空值并标记来源。
3. 996PC 的锚点 `a/ax/ay`、百分比坐标、自动尺寸、ListView 惯性/回弹/裁剪等布局行为目前保留参数并做静态近似，不是客户端布局引擎的像素级复刻。
4. 客户端字体字形、描边、发光、DMode 着色器、Blend、声音、原生提示窗口皮肤和脚本标签实际执行不在 Webview 中运行；文字备注语义已模拟，但不是客户端窗口像素级复刻。
5. 动画中缺失的缓存帧会被跳过；超过 240 帧只预览前 240 帧。
6. `ITEMSHOW` 的 StdItem 内观、称号模式、物品特效等运行时绘制开关会显示参数，但 Webview 暂不模拟客户端内部特效管线。
7. 自动“移动编辑器到新窗口”依赖 VS Code 版本提供 `workbench.action.moveEditorToNewWindow`。代码已有能力检测和标签页回退，但真实 Electron 浮动窗口命令无法在 Headless Edge 中自动验收，仍需在目标 VS Code 版本做一次人工点击确认。
8. 素材准确性最终依赖用户工作区绑定的客户端目录、补丁优先级、EffectImageList、缓存有效性和数据库字段正确；缺失时会明确显示资源名、序号和未缓存状态。

## 8. 结论

新的 Ctrl+F12 DOM 面板已经形成独立、可测试、可回写且不影响原 UI 编辑器的完整系统。当前已收录的三引擎界面语句全部能进入 DOM 模型；核心条件、变量、素材、容器、动画、交互和保存链路均通过单元测试、真实浏览器测试与项目全量回归。剩余差异主要来自游戏运行时状态和客户端内部布局/特效引擎，已被明确隔离，不会伪装成准确结果或破坏原 TXT。
