# 大包与百万槽压力验收：历史基线、紧凑目录和验收边界

日期：2026-09-26。用途：区分已完成的生产实现、历史大数组基线和当前候选验收，避免把后端索引通过等同于画布交互通过。

## 结论

**生产后端的百万槽稀疏索引、尾 ID 随机读取，以及 30,000 张有效图片的整包验证、取消、续跑均已通过。之后已实现紧凑目录传输和有界前端存储，并通过工作区百万槽 Chromium 测试；最终 `scale-r1` 候选的百万槽原生 VS Code Webview 和独立收尾审计均已通过。**

历史基线中，实测百万槽后端返回的 `assets` 富对象数组，序列化尺寸为 **379,777,831 字节，约 362.2 MiB**。旧 UI 发送前还为每项追加 Webview URL、复制对象，收到后再构造过滤列表。这些已被本轮紧凑目录路径替换；该数值保留为修复前基线，**不再代表新 UI IPC 大小**。

新后端 builder 的百万槽/3 张图描述符为 **574 字节**；完整生产 HTML 的 Chromium 测试使用带内嵌测试图 URL 的描述符，为 **637 字节**，完整 `fullState` 为 **953 字节**。这些是不同夹具/URL 下的数值，不能混称同一包。原始逻辑 ID 和全部空槽均保留。

最终原生 VS Code Webview 使用正式 `asWebviewUri`，目录为 **653 字节**、完整 `fullState` 为 **964 字节**。原始 ID **999999** 可通过精确输入显示真实图片；空槽、动画原点、进度条两次保存与 willIdx 均通过。

Host 内部 `loadedPakResults` 富对象数组尚未重构；本轮收紧的是 Host→Webview 传输和前端物化链路，不宣称消除了 Host 的 O(槽位数) 内存。

## 当前紧凑目录实现和工作区验证

- `src/utils/archive-asset-catalog.ts`：每包共享身份、profile、generation、来源和 URL 模板；仅传非空/拒绝槽元组。legacy 文件只传公开白名单字段，不展开解析器、密钥或缓存内部状态。一次包级 URL 转换代替逐槽转换。
- `src/extension.ts` 的 `postLoadedPakAssets`：生产消息使用 `assetCatalog`，不再展平并复制 direct 槽位。
- `media/editor.html` 的 `createAssetStore`：按包范围定位、按需物化、最多 1024 个富对象缓存；计数和主列表过滤使用紧凑记录/范围视图；同一来源通过稳定身份比较，不依赖 LRU 后仍是同一对象。
- 完整/浮动画布状态发送可序列化目录，不发送 Proxy 或隐式展开百万槽；legacy 文件夹、跨包同 ID、状态更新、追加和源替换保留。
- malformed direct 目录先校验再更新 UI 状态：非法几何、槽位、来源、状态、URL token 和矛盾失败原因不能污染当前目录/模式。

已执行：`npm run compile`、新模块 ESLint、`tests/archive-asset-catalog.test.js` 和 `tests/archive-asset-store-browser.test.js`。后者运行完整生产 HTML 的 Chromium DOM，百万槽加载 69.80 ms、描述符 637 字节、完整状态 953 字节；该工作区时刻计时只表示一次运行，不是性能保证。原生候选结果应以之后的固定哈希 `scale-r1` 为准。

后端测试还覆盖 mixed legacy、跨包 ID/generation、未知 profile 原样保留、未知状态拒绝、1×1 空槽默认值、32 位偏移、坏 URL 模板和密码/解析状态不泄漏；前端测试覆盖 1024 缓存上限、一列滚动至 ID 999999、状态序列化、非法目录拒绝和源替换。控件操作为合成 DOM 事件，不是原生鼠标键盘或游戏客户端。

## 内存与事件循环的解释边界

百万槽样本：

- 构造生产富对象之前 RSS：49,364,992 字节。
- `openArchiveIndexed` 返回后 RSS：251,437,056 字节，V8 heap used：191,681,424 字节。
- 同时持有富对象、Worker 和紧凑表时 RSS：278,974,464 字节。
- 紧凑表自身为 15,000,000 字节；富对象 JSON 为 379,777,831 字节。
- 工具为准确计算 JSON 字节数而逐项序列化，增加了垃圾分配。全进程 RSS 高水位 419,180,544 字节**包含这项工具工作**，不能称为纯生产解码峰值。

密集包全进程 RSS 高水位 206,479,360 字节。同样包含夹具构造、测量工作和同进程 Worker；报告保留阶段检查点，避免把所有内存统一归因于产品。

事件循环有两组指标：

- `maxEventLoopGapMs`：整个采样窗口，包括工具自己的 JSON 尺寸统计。
- `productionMaxEventLoopGapMs`：排除 `harness*` 和阶段间隙，只计算生产调用。百万槽的 437.73 ms gap 来自工具逐项序列化，正式生产调用的最大 gap 为 75.10 ms。密集包的 152.49 ms 出现在索引打开阶段，仍是后续可优化的主线程同步工作。

首图计时为**源包索引入口加 Worker 返回 PNG**，不是 Webview 图片 `load`、像素首绘或原生键鼠体验。

## 修复前确认的 UI 放大链路

以下为促成本轮修复的旧生产路径快照，不是当前待办清单：

1. `postLoadedPakAssets` 将各包 `assets` 展平，再复制每个富对象、构造每槽 URL，并发送 `loadAssets.files`。
2. `renderAllAssets` 全扫槽位生成标签，再全扫生成 `{asset, originalIdx}` 过滤包装。可见 DOM 虽然虚拟化，前面的富对象列表没有虚拟化。
3. `archiveAssetCounts` 全扫；状态刷新又对 `_virtualList.filteredItems` 做 `map` 后计数。
4. `findAssetIndexByCode`、`getEffectFrameAsset` 和 ID 定位使用全量查找。
5. 修复前，图片、按钮、特效、关闭按钮、装备框、进度条六种选择器均有全量生成 HTML 的路径。最先修复的进度条改为每页 96 项，之后的其余选择器单独分页；当前实现与最终验证见总报告，不能把此历史列表当未修清单。
6. 动画按起始 ID 和数量取帧时，当前实现先 `folderAssets.forEach` 扫整个包。
7. `getFullState` 和 `syncCanvasToCode` 的浮动画布消息包含完整 `folderAssets`。即使宿主没有对应处理路径，构造/发送这份消息也不能忽略；引入 Proxy 后更不能直接通过消息传输 Proxy。

因此，“只给 `folderAssets` 套一层 Proxy”或“只把富对象换成 typed array”都不是闭环修复。

## 本轮采用的兼容方案

已经选择并实现同步紧凑描述符和惰性视图作为第一步，避免同时把所有现有随机下标消费者改成异步请求。以下是方案合同；不等同于所有列出的验收均已经完成。

### 传输合同

- 对 `direct` 包发送包级共享字段：`archiveId`、`indexGeneration`、`profileId`、`pakName`、`pakPath`、`willIdx`、`slotCount` 和可构造资源 URL 的模板。
- 只传非空/拒绝槽的紧凑记录：`[logicalId,width,height,offsetX,offsetY,status,reasonCode]`。空槽可由 `slotCount` 和缺省记录推导，保留原始逻辑 ID。
- 首版用纯 JSON 数值元组，不未经验证地依赖跨宿主桥的 typed array/Transferable 行为。若采用固定长二进制加 Base64，则必须为整数范围、版本和损坏长度增加解析门槛。
- `legacy` PNG 文件夹路径继续使用现有对象数据，避免破坏不属于 direct 归档的导入流程。
- Host 原来的 `loadedPakResults`、数据库和地图消费者暂不更改；紧凑化先止于 UI 传输边界。之后另测 Host 富对象内存是否值得继续收紧。

### 前端存储合同

在生产 HTML 中使用独立的 `createAssetStore` 段，提供同步 `get(index)`、`find(will,id)`、`count(filter)`、`packages()`、`view(filter)`、`serialize()`；兼容层保留 `folderAssets[index]` 和 `.length`。

- 仅对可视条目、当前选中项和最多 240 帧动画创建富对象，不为计数和标签创建对象。
- 主列表的 `_virtualList.filteredItems` 改为惰性范围视图，不能再形成百万个包装对象。
- ID、代码引用、动画取帧走包索引；动画最多访问请求的帧数。
- 六种选择器共用按包、搜索和每页最多 200 项的范围组件。提供明确下一页/上一页或虚拟窗口，不可默默截掉后部槽位。
- `fullState` 发送可序列化描述符或已有素材会话引用；收到时重建存储。禁止发送 Proxy 本身，也禁止通过 `JSON.stringify(proxy)` 隐式展开所有槽位。
- 状态回包更新存储记录和计数差量，再更新当前可视条目。覆盖值必须受 `archiveId`、`indexGeneration` 和前端会话 generation 保护。
- 现有 hover/inspector 使用对象引用相等判定。若惰性对象缓存有 LRU，必须 pin 活跃消费者或改为稳定身份判定，不能因缓存淘汰把同一图误判为新来源；也不能以无限对象 Map 换来身份稳定。

### 该方案仍需保留的边界

百万槽稀疏包的传输已缩小为包级元数据和三个记录；百万张全部非空的包仍需要 O(有效记录数) 的紧凑元数据。这比数百 MiB 富对象合理，但还不是“所有包、所有 IPC 均固定上限”。若要求严格固定的单次 IPC 和内存上界，必须进一步采用分页请求，届时同步消费者需要异步化或缓存缺页状态，属于下一层改造。

### 必须具备的验收

1. 百万槽三张图：描述符小于 10 KiB，逻辑 ID 999999 可读，空槽不丢失。
2. 跨包同 ID、不同 will；负偏移、尺寸、失败状态和原因值保持一致。
3. 同时兼容旧式 PNG/legacy files；追加、重载、关闭包、重新排序不串 ID。
4. 物化对象数不超过当前窗口、活跃选择和动画范围的明确定额；计数、包标签、查找不得物化全部槽位。
5. 六种选择器每页 DOM 不超过 200 项，最后一页可到达；搜索和包过滤不会因分页而漏掉后部结果。
6. 动画保留缺帧/坏帧，连续 ID 与共同原点不受存储改造影响。
7. `fullState` 不展开富对象，前端切换 generation 后旧回包不能污染新素材。
8. 状态 delta 后数量、详情、当前缩略图同步；对象缓存淘汰不导致 inspector/hover 异步失效。
9. 在完整生产 HTML 的 Chromium DOM 中覆盖六类选择器；在隔离 VS Code Webview 中覆盖紧凑 IPC/完整状态、实际图片资源、末尾 ID、动画、进度条双保存和取消续跑。记录可取得的计时与 Host RSS，不能将 Host RSS 采样称作 Webview 峰值内存，也不能将图片自然尺寸/load 断言称作原生键鼠或客户端验收。纯 VM 或后端测试不能代替这两层。

本轮测试调用已实施的生产 builder 和完整生产 HTML；最终是否满足上述各项，以固定新候选的实际结果为准，不以旧 r2 通过或设计合同代替。
