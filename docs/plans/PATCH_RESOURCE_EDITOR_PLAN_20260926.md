## 1. 目标与范围

### 新增地图待办（2026-09-26，用户追加）

这两项独立于资源工作台 P2 的完成判定。MAP-01 已修复引擎规则能够证实的 QuestDiary 路径误判，红绿回归通过，但用户具体报错调用尚待对照；本地测试服当前扫描仍为 590 定义且无缺文件报错。MAP-02 已实现地点文字标记，真实 Chromium 绘制与切图回归通过。

| 编号 | 问题/需求 | 排查与验收标准 |
| --- | --- | --- |
| MAP-01 | 永久 `MAPEFFECT` 原始地图绘制显示“启动脚本扫描失败，调用目标文件不存在”，但用户确认文件存在 | 用发生报错的完整启动脚本与目标文件复现，核对服务端根目录、相对调用路径、中文/空格及文件名编码；存在的目标必须被正确解析并显示永久特效；真正不存在时仍给出准确诊断，不靠吞掉错误通过 |
| MAP-02 | 原始地图右下角预览图增加地点文字标记（用户已明确：不是地图编号） | 按地图格坐标映射到导航图、保留颜色，大/小地图重复标记去重；切图清除旧标记；长文字可截断并悬停查看完整值；不拦截导航拖动和缩放；三档窗口均可读 |

顺序：完成当前 JPK 编辑阶段的验收后，先处理 MAP-01，再处理 MAP-02，随后回到资源工作台后续阶段。尚缺出错地图标识及具体启动调用位置时，先从现有报错链路定位；无法复现则保留“待验证”，不能标记已修复。

在现有“补丁管理”中提供 GM 资源编辑器式的素材操作：浏览、导入、导出、替换、填充空槽、追加、清空槽位、调整偏移、批量处理、动画检查、撤销/重做及安全保存。

采用“补丁管理侧栏作为入口，编辑区标签页中的工作台负责编辑”的方案；不自动打开独立窗口。保留现有引擎、客户端目录、密码配置、资源优先级、需求读取和缓存体系。界面沿用 BOO 新版简洁样式与“老卢”图标，参考 GM 的操作习惯，不直接复制受保护程序界面代码，也不内嵌整套 GM EXE。

范围是资源包编辑，不包括 GM 套件中的数据库编辑器、地图编辑器或独立特效生成工具。跨包复制、格式转换等列为后续增强，不阻塞核心导入、导出和偏移功能。

计划编制时仅查看代码和已有资料；下文“已有基础”保留该时点的源码核对结果，不能当作最新进度。开始实施后的功能、实际测试与候选包以顶部进度表和 P1 报告为准。本轮没有运行 GM 参考 EXE、重写真实素材包或替换默认扩展安装；隔离测试安装与用户默认安装分开记录。

建议主界面：

```text
补丁管理侧栏：现有包列表 → 右键/按钮“打开资源编辑器”

┌ 老卢  包名*   打开  导入▾  导出▾  撤销  重做  保存▾  更多 ┐
│ 素材列表 / ID定位      │ 原图或动画预览        │ 图片属性    │
│ 100项分页             │ 棋盘/黑/白底          │ ID、尺寸    │
│ 多选、范围选择        │ 原点十字、参照图      │ X、Y        │
│ 空槽/修改筛选         │ 拖动偏移、缩放/平移   │ 单张/批量   │
│                       │ 动画范围及播放控制    │ 应用/重置   │
├ 简短任务进度、取消；错误与详细日志按需展开                  ┤
└───────────────────────────────────────────────────────────┘
```

- 工作台在当前 VS Code 窗口的编辑区标签页内打开，不自动弹出独立窗口；同包复用标签页。此次要求仅针对资源工作台，不改变 UI 编辑器或 Ctrl+F12 的窗口行为。保留选中项、草稿和滚动位置。
- 普通包只显示高频按钮；只读或部分可写包给简短状态，禁用操作可查看一行原因。不要恢复此前去掉的冗长“槽·图·空”统计和整屏解释文字。
- “导入”指图片写入资源包草稿；“添加补丁目录”“导入密码表”保持原名称，避免三个不同动作混称导入。
- “删除”在界面中明确为“清空所选槽位”，默认不移除 ID、不挤动后续图片；会重排 ID 的操作不放入常用按钮。
- X/Y 输入、拖动图像和方向键微调属于同一偏移操作；手形平移工具只移动视口，不能改图片坐标。参考背景/原点固定。
- 常用快捷键仅在编辑器有焦点时生效；输入框编辑不会误触删除，Ctrl+Z 优先撤销当前输入或资源编辑操作，不影响脚本编辑器。
- 900×700、1100×800、1440×960 三档布局验收；窄窗口可折叠属性，不让工具栏挤占主要预览区域。

## 4. 功能定义与数据规则

### 4.1 导出：首先保证可还原

支持单张、选中项、ID 范围、整个包；第一版以无损 PNG 和目录为主，后续增加 ZIP、动画及精灵表。

- 文件名使用原始逻辑 ID，例如 `001927.png`；空槽、坏槽不导致后续重新编号。
- 同时生成带 schema 版本的清单：原包标识、profile、ID、尺寸、X/Y（未知为 null）、槽位状态、像素摘要、可知的透明/混合元数据等；密码和密钥不进入清单。
- 导出前明确选项：原包内容或包含当前草稿的内容。不能偷偷把未保存修改当原图导出。
- PNG 自身不承载本项目完整偏移和槽位语义，坐标必须通过清单恢复。GM 坐标文件格式只有取得格式证据或实际样本后才声明兼容，不猜测语法。
- 本地独立 GM 实现已有自有 `GMResourceEditor.coordinates.v1` 坐标 JSON，可做版本化适配；它不是原版 GM 坐标文件兼容性的证据。
- 失败/跳过逐项列出；不输出伪造的正常空白图掩盖损坏。可提供空槽清单，不强制导出空白 PNG。
- 批任务支持进度/取消；取消或失败保留明确“未完成”状态，不将半成品目录或 ZIP 标成导出成功。

### 4.2 导入：先预检映射，再修改草稿

先支持 PNG/BMP，按能力开放：替换所选、按 ID 批量替换、填充空槽、从指定 ID 导入、追加到尾部。

- 导入前显示“源图片 → 目标 ID → 操作”的预检表；重复 ID、占用冲突、越界、尺寸超限、坏图、不能表达的颜色/Alpha 必须提前报出。
- 按 ID 与顺序追加是不同模式；自然数字排序必须稳定，禁止靠文件系统枚举顺序隐式决定 ID。
- 替换默认保留原槽位偏移；存在有效导出清单时可明确选择恢复其偏移；新槽没有坐标数据才使用已知默认 0/0，不把未知坐标伪装为 0。
- Alpha、调色板、黑色透明和压缩方式由 profile 决定；无法无损表达时默认拒绝，若后续提供有损转换，必须明确选择并显示对比。
- 批量动作先验证整批，再成为一个可撤销操作；默认全有或全无，不静默跳过后显示整批成功。
- 图片写入编辑草稿，不立即改源包。超大图片和解压数据设上限，导入路径由宿主选择，清单不得越目录引用文件。

### 4.3 偏移：区分存储坐标与画布坐标

- 单图 X/Y 输入、拖动、方向键微调、恢复原值；数值范围来自各 profile，不把所有格式硬编码为同一范围。
- 批量“设为绝对 X/Y”与“整体增加 ΔX/ΔY”分开；应用前显示影响范围，跨页多选保留稳定 ID。
- 连续拖动只在本地/草稿合并更新，松手记一个撤销步骤；不能每一帧都重建包。
- 支持固定原点、参照图、前后帧叠影；动画在同一原点播放，不逐帧居中掩盖坐标跳动。
- 裁透明边后，必须按已验证坐标约定补偿偏移，使裁剪前后的世界位置不变；没有证明的 profile 不开放此类联动。
- 对“legacy 坐标未确定”等情况只展示读取边界，不开放偏移写回。

### 4.4 其他常用编辑及后续增强

- 首批核心：替换、填空、追加、清空槽位、撤销/重做、脏状态、关闭/切包保护。
- 批量增强：同包/跨包复制、批量偏移、数字 ID 映射、导出/导入清单往返、重复素材检查。
- 图像增强：裁透明边、镜像、缩放、画布尺寸调整；逐项定义 Alpha、插值和偏移规则，禁止隐藏颜色损失。
- 动画增强：连续帧/用户自选帧组、步进/帧率/反向、参照物、PNG 序列、GIF/APNG、精灵表。GIF 色数/透明限制要明示，序列 PNG 作为无损基准。
- 包级增强：新建已知格式、同格式安全重建、支持矩阵内的格式转换、包差异及选择性同步。转换有能力检查和损失报告，绝不默认“转换一下就能修好”。

## 5. 唯一主线架构与复用决策

采用 **VS Code Webview + TypeScript 宿主 + 隔离写入 worker**。保持当前 BOO 读取、按需解码和缓存架构；从历史 BOO JPK 原型和本地 GM 实现提取经核查的编辑模型、writer 与事务能力。writer 的既有实现主要为 Python，建议以受控打包 worker 接入，不要求用户安装 Python；最终依赖体积、来源及启动成本在阶段 0 核对，不为此另起桌面壳。

```text
Webview：sessionId / logicalId / revision / 受限操作
    ↓ 宿主校验、能力判断、路径对话框、任务排队
ArchiveEditSession：源身份 + profile + 稳定槽位 + ChangeSet + Undo/Redo
    ↓ stdio 或命名管道；握手、请求ID、取消、超时
格式 writer → 候选输出 → BOO 生产 reader 验证 → 事务发布
    ↓ 保存成功后的版本事件
补丁管理 / 素材选择器 / UI编辑器 / Ctrl+F12 / 地图缓存更新
```

- 中间模型包含逻辑 ID、原始块引用、归一化 RGBA、尺寸/偏移/已知格式元数据、原始未知字段及变更集；未知字段不编造默认值，未改块尽量字节保留。
- Webview 不拿密码、不传任意写路径；宿主和 worker 双重检查操作能力。密码不进 argv、日志、导出清单或历史记录，worker 退出时释放会话。
- 保留 `boo-archive:` 的只读约束。写入不是给现有文件系统 provider 或固定端口只读 HTTP 桥增加几个写接口。
- worker 使用隐藏子进程和版本握手，不新增无认证固定端口；大图片通过受控文件/二进制引用传递，不整包 Base64 塞进 Webview。
- 一包一个写会话，多个视图共享会话；源文件发生外部变动时阻止覆盖，允许重新打开或另存，不静默合并。
- 新增源码建议：`src/resource-editor/`、`src/providers/resource-editor.ts`、`media/resource-editor.html`、共用素材浏览组件、worker 协议与格式适配层。迁移只选相关模块，不能把旧原型 120 项分页或旧 reader 整树覆盖当前代码。

### 来源与分发前置门槛

本轮在 GM 本地实现根目录未找到明确的根 LICENSE/NOTICE；这不是认定代码不能使用，但不能据此假定所有代码和二进制均可随 VSIX 再分发。其 GEE 密钥路径还含从参考 EXE 抽取的 VM snapshot。必须核对自主代码权属、第三方依赖及该资源的来源/许可，未明确前不复制这部分资源进新编辑功能。必要时保留相关分支只读，采用来源清楚的独立实现；不阻塞不依赖该资源的 JPK 等首个闭环。

| 1 | 996PC/XUW GameLib JPK 的已确认分支 | 完成单包导入、偏移、撤销、另存闭环 | 历史 BOO JPK 原型最接近现有宿主；真实样本、像素、元数据和失败注入通过才开放 |

只读包仍可浏览和导出能确定的图像；某一分支未完成不应禁用所有 PAK 的编辑。

## 7. 保存安全与缓存一致性

保存采用：**检查源身份 → 同目录候选构建 → flush/fsync → 独立生产 reader 重开 → 槽位/像素/元数据核对 → 发布**。

1. 初版默认“另存为”，源包 SHA-256 前后必须相同；覆盖模式在备份、恢复和失败注入验收后再开放。
2. 对源包及已存在的目标做外部修改检测；不能在用户确认后无条件覆盖后来变化的文件。只读文件、目标占用、磁盘不足要明确失败。
3. 未修改块在格式允许时保持原字节；所有未修改槽位的 RGBA/元数据一致，修改槽与期望值一致。像素相等不能替代未知字段保真要求。
4. WIL/WIX、WZL/WZX 两文件按组写日志、备份和恢复；不得称两次 rename 为单次原子操作。第二文件失败或进程退出后，下次打开能识别并恢复到完整旧组。
5. 取消在验证/发布前生效；进入不可分割提交段后界面明确“正在完成保存”，不能承诺此时硬杀也一定无损。
6. 坏槽、恢复槽及未知附加数据默认阻止普通全包写入；只允许在证明可无损保留的情况下继续，或通过另存/显式修复流程列明损失。禁止静默丢弃。
7. 保存副本不自动替换当前客户端绑定或资源优先级；由用户明确选择采用副本。保存成功不自动改 Pak.txt、JpkList.txt 或 EffectImageList.txt。
8. 保存发布新版本事件，按包失效索引、PNG/进行中解码、浏览器图 URL、侧栏素材表和地图素材缓存；旧异步回包必须被 generation/revision 丢弃。
9. 未保存草稿只影响资源编辑器，不污染 UI、Ctrl+F12 或地图的正式预览。需要跨视图预览草稿时另做显式模式，不默默替换正式资源。
10. 发布后重开、缓存更新或通知失败，应返回“文件已保存、后续步骤失败”的明确回执和恢复指引，不能报成“未保存”诱发重复覆盖。

## 8. 实施顺序与逐阶段验收

| 阶段 | 交付内容 | 必须满足的验收标准 |
| --- | --- | --- |
| P0 基线和复用审查 | 功能台账、profile能力表、依赖/来源清单、固定样本、迁移范围 | 主工程现有读取回归不退化；逐项区分可读/可写/待验；未明确权属资源不纳入包；样本只读且记录SHA |
| P1 工作台与导出 | 补丁管理入口、编辑区标签页工作台、100项/ID定位、多选、预览、PNG+清单导出 | 不自动弹窗；ID定位后邻近素材仍可浏览；空/坏槽不改号；透明度及已知偏移可回读核对；三尺寸可操作；取消不伪报成功；原包SHA不变 |
| P2 第一个编辑闭环 | 已确认JPK：单张替换/填空/追加/清空、X/Y、撤销重做、另存及关闭保护 | 打开→导入→偏移→撤销/重做→另存→BOO reader重开全部成功；负数/0/范围边界验证；未改槽一致、原包SHA不变；失败不发布 |
| P3 PAK及成对包适配 | 按第6节依次接GOM/GOM2、GEE、WIL/WZL；单包能力控制 | 每个profile独立跑编辑矩阵；legacy不能误开坐标/追加；未知分支保持只读；双文件中途失败整组恢复 |
| P4 批量与保存联动 | 批量导入、替换、偏移、跨页选择、同/跨包复制、安全覆盖、版本事件 | ID映射和冲突预检准确；整批撤销、失败不半提交；外部修改阻止覆盖；保存后补丁/UI/Ctrl+F12/地图见新图；草稿不污染正式缓存 |
| P5 常用增强 | 动画检查与导出、参照物、裁剪/镜像/缩放、包新建/重建/矩阵内转换 | 原点稳定；裁剪不移动画面位置；GIF等损失可见；每条转换有源→目标像素/元数据核验，未知字段损失不得隐瞒 |
| P6 最终深测与交付 | 原生宿主测试、实际交互、大包性能、失败恢复、隔离VSIX、操作说明与报告 | 候选包中的代码本身通过回归；保留旧包和恢复方法；记录通过/失败/跳过；真实客户端/GM参考验证单列，缺证据不宣称全格式兼容 |

首个对用户有价值的可交付版本为 **P1 + P2**；核心常用编辑覆盖在 **P4** 收口。P5 不阻塞已验格式的正常使用，P6 不得用文档完整或测试数量代替真实保存结果。

## 9. 深度测试清单

- **内容与编号**：首/末槽、连续空槽、稀疏百万槽、ID 0、跨页多选、清空后再填、追加、重复文件名、中文/空格/长路径；任一操作不意外重排 ID。
- **像素与坐标**：全透明、黑色、半透明、奇数宽、调色板、不同位深、正负偏移、格式边界、不同原点、裁剪补偿；保存再开与源图/期望元数据对照。
- **事务与故障**：错密码、截断包、坏图片、权限拒绝、目标占用、写满/短写、解码失败、保存中断、取消、源被外部工具修改；检查原包/旧目标和恢复日志。
- **历史与多视图**：拖动一次撤销一步；多次撤销重做；切包、关闭、重开、worker退出；两个视图编辑同包不互相覆盖；旧异步请求不恢复旧图。
- **缓存**：保存改变一个图及偏移后，检查补丁工作台、UI素材、Ctrl+F12 ITEMSHOW/动画和地图的对应资源；清理仅限目标包版本，不能删全局缓存掩盖问题。
- **性能**：至少2万图与100万稀疏槽；维持100项分页、按需解码和有界缓存；只改偏移时RGBA摘要不变且无重复全图解码；记录首屏、ID定位、批处理吞吐、峰值内存和取消延迟。
- **性能目标**：索引已就绪、素材已热缓存时，ID定位/翻页的交互确认目标≤100ms；偏移输入到局部预览目标≤50ms；批任务取消确认目标≤1s。冷盘解码/写盘单独记录P50/P95及机器/样本，不能把目标写成当前成绩或抹掉长尾耗时。
- **安全与发布**：恶意消息、过期session/revision、越界ID、导出路径穿越、解压上限、密码日志扫描、依赖与worker闭包；非管理员、中文安装路径及原生VS Code隔离配置启动。
- **证据分层**：源码检查、单元/合成向量、真实包round-trip、Webview合成事件、原生鼠标键盘、参考工具重开、游戏客户端分别列结果。任何SKIP均不得算PASS。

## 10. 关键风险与不作承诺的范围

1. 未知格式和损坏数据：密码不能补回截断字节；同格式重建只能处理明确可恢复的问题，不等于万能修复。
2. GM行为对等：本轮没有动态遍历参考EXE，不承诺逐按钮、逐像素或全部内部算法相同；按明确功能和验收结果对齐。
3. 历史代码漂移：GM旧路线表与当前源码存在时间差，历史“完成”或“未实现”均不能直接作为本项目现状。
4. 编码损失：无Alpha格式、调色板、GIF等存在表达限制；默认保真，转换损失需明确确认。
5. 来源和分发：VM snapshot及第三方组件需核查，不以本机能运行作为可随包分发的依据。
6. 用户源数据：任何格式在进入可写名单之前必须通过独立保存门槛；真实资源仅用副本测试，不自动重建原包。
