# 只读检查 PAK 原始结构

目的：导出可追溯的图片槽位、字段布局、文件区间和未知边界，不转换或改写素材。当前为开发诊断入口，不是已发布的VS Code按钮。

## 1. 编译

在项目根目录执行 `npm run compile`。运行时不需要安装外部引擎源码。

## 2. 提供检查输入

执行 `node tools/pak/inspect-structure.js`，通过**标准输入**提交一个JSON对象。不要把密码放在命令行参数、提交的配置文件或日志中。文件路径使用JSON转义后的反斜线或正斜线。

| 字段 | 要求 |
| --- | --- |
| files | 1至100个明确的PAK文件路径；不会自动遍历磁盘 |
| password | 本次临时使用的密码字符串，保留尾部空格；不会保存 |
| reportFile | 新报告JSON路径；已存在则拒绝覆盖 |
| maxReportSlots | 可选，默认20000；范围1至100000，超限明确拒绝而不截断报告 |
| useRunningBridge | 可选，默认false；设true才允许请求配置端口上的现有离线引擎，不负责启动它 |

也可通过 `npm run inspect:pak-structure` 使用相同标准输入协议。

原始PAK只读打开；工具不会清缓存、生成转换包、写入原图或启动GM/游戏客户端。报告只能新建，误选原PAK作为报告目标也会拒绝。

## 3. 检查结果

- 进程码0：所有目标均已完成结构检查且未发现结构问题。
- 进程码2：至少一个目标无法检查或发现结构问题。查看报告中的对应项，不能把生成了报告当成全部成功。
- 进程码1：输入或报告写入失败。

每个成功检查的文件包含文件摘要、实际读取器摘要、格式合同、原始槽位、空槽、拒绝块、图片位置、尺寸、偏移以及未分类字节区间。

注意：`indexed-unverified` 不是“图像已正确显示”；本命令不解码全部像素。像素回归、Worker回归、VS Code实际显示与客户端效果分别验证。GEE legacy的未解码坐标输出null，不把默认0称为真实偏移。

## 4. 核对源码证据版本

有本机GXX源码时，可执行：

```powershell
node tools/pak/verify-source-evidence.js "<GXX 源码根目录>"
```

请将示例路径替换为自己合法持有的对应源码目录；仓库不提供厂商源码。六个参考文件应全部 `matches=true`。它只读取并计算摘要，不编译或执行原源码。摘要不匹配时，不应继续把旧行号与旧结论当成当前源码的确定事实；应重新核查对应版本。

字段及未知范围见 [PAK可追溯结构规范](../specifications/PAK_STRUCTURE_CONTRACTS_20260925.md)。
