# 补丁资源工作台：浏览、导出与资源编辑

适用：V4.3.7 源码及配套发布包，支持受限 JPK、GAMEOFMIR2 PAK 及 Windows WIL/WZL 成对编辑。旧版候选不会自动获得新增功能，需安装最终发布包。工作台在当前 VS Code 标签页内打开。历史实现与验收边界见[实施计划](../plans/PATCH_RESOURCE_EDITOR_PLAN_20260926.md)。

## 打开

1. 在“补丁管理”选择客户端与相应密码配置，使用高速模式读取需要的资源包。
2. 选中已缓存的包，点击“素材”；也可以执行命令 **BOO: 打开补丁资源工作台**。
3. 工作台在当前 VS Code 窗口的编辑区标签页中打开，不自动弹出独立窗口。同一包再次打开会复用标签页。

本阶段只接入已读取的 direct 高速索引。旧版 PNG 缓存请切换高速预览并重新读取；这不会自动删除旧缓存。包发生变化后，需要在补丁管理重载再打开工作台。

## 浏览

- 每页 100 个逻辑槽位，左侧固定每行 5 个，共 20 行，向下滚动查看本页其余素材；空槽仍保留编号。页码 `1 / 36` 表示第 1 页、共 36 页，不是每页 36 个。
- 输入 ID 并点击“定位”，跳到所在页并高亮，附近素材仍然可见。
- 点击查看原图；Ctrl 多选，Shift 连选，支持跨页保留选择。“选本页”“清选择”用于批量选择。
- 手选最多 10000 项；更大批次请使用 ID 范围或全包导出，不需要手工选满整包。
- 支持棋盘/黑/白背景、50%–800%缩放、偏移与原点视图。拖动只平移视口，不修改资源坐标。
- 未知坐标显示“未知”，预览参考值不是包内真实字段。空槽、损坏、不支持与读取失败分开显示。

## 导出

右侧选择“当前素材 / 已选素材 / ID 范围 / 全部素材”，点击导出并选择目标目录。

工作台在该目录下新建唯一 `boo-export-…` 子目录，不覆盖已有导出或源包：

```text
boo-export-…/
  000000.png
  000002.png
  …
  manifest.json
```

PNG 名称保留原 ID，不因中间空槽重新编号。清单保留导出范围、逐槽状态、宽高、已知偏移、像素/压缩/透明信息、图片 SHA-256、源包与配套索引前后 SHA-256。未知偏移为 `null`。它是 BOO 自有格式 `boo.archive-export.v1`，不宣称是原版 GM 坐标文件。

只输出能够正确解码的图片，空槽不输出替代 PNG，失败项保留在清单。取消会停止后续图片处理；最后仍核对源文件哈希，大包的收尾校验可能需要时间。

清单 `state` 含义：

- `complete`：所选范围已处理，非空素材均成功导出，源身份核对通过。
- `partial`：包含失败项、源文件变化或运行中断，需要检查 `reasonCode` 和逐项记录。
- `cancelled`：用户取消；已导出部分保留，不能当作完整备份。

若磁盘已无法写入清单，可能保留未完成 JSON/`.incomplete` 文件，界面不会报告成功。这些都是本次新建的导出产物，可在确认不需要后自行删除；工作台不会自动删用户目录。

## 编辑 JPK / GAMEOFMIR2 PAK

1. 打开已读取的 JPK 或 GAMEOFMIR2 PAK，点击右上角“开启编辑”。优先使用补丁管理已有密码；缺少时由宿主安全输入框询问，不保存到脚本或页面。
2. 等待逐图核验。支持已验证的 GameLib / 996M2 / GAMEOFMIR2 v2 分支。GAMEOFMIR2 中未索引的历史图片记录可经完整解码核验后兼容，另存时保留其原始字节，不增加逻辑 ID；无法解释的间隙、未知尾段、损坏槽及重叠块仍保持只读。失败原因会留在顶部提示中，不会立即变为“就绪”。旧 GAMEOFMIR 不因扩展名相同而开放编辑。
3. 选中素材后，可“替换”、输入 X/Y 后“应用坐标”；选中空槽可“填空”。“追加”在末尾创建新 ID。“清空当前槽”保留编号，后续素材不移动。
4. 导入使用宿主 PNG/BMP 选图框，确认文件名与目标 ID 后进入草稿。替换保留原偏移；新槽默认 X/Y 为 0。X/Y 范围为 -32768 到 32767。
5. “撤销”“重做”作用于本资源会话，最多保留 100 步，草稿与历史合计受 128 MiB 限制。
6. 点击“另存新包”，选择**不存在的新文件名**。工作台构建临时包、逐图回读验证后才发布；既不覆盖源包，也不覆盖已有文件。成功后工作台切到新包，清空撤销历史。
7. 结束编辑或关闭标签页时，未保存草稿会询问另存、放弃或继续。关闭标签页不能被 VS Code 阻止，因此“继续编辑”会恢复标签页和本次草稿。

编辑期间 PNG 导出暂时禁用，以免混淆源图与草稿。另存成功并结束编辑后，可导出新包。新包**不会自动替换补丁管理、UI 编辑器、Ctrl+F12 或地图所绑定的原文件**，需用户另行选择采用新包。

### 导入与保存限制

- PNG：8 位、非交错；支持灰度、RGB、调色板、灰度 Alpha、RGBA。暂不接收 16 位、交错、APNG、ICC/EXIF 等布局。
- BMP：40 字节 DIB 的未压缩 24 位，或明确不透明的 32 位 BGRX；有不明确 Alpha 的 BMP 请转为 PNG。
- 导入文件不超过 32 MiB，宽高各不超过 4096，总像素不超过 4194304；宽高都不超过 2 像素的图不在当前 JPK 支持范围。
- 替换保持原槽位像素布局。调色板、RGB565 或无 Alpha 槽无法无损表达导入图片时，明确拒绝，不自动降色或丢透明。
- GAMEOFMIR2 的非 Alpha 16/24/32 位图片采用纯黑透明：半透明像素、不透明纯黑、透明且带非黑 RGB 的像素无法原样表达，替换会拒绝。需要保留这些像素时，可填空或追加到新建的 32 位 Alpha 槽；不会自动改变原槽位格式。
- GAMEOFMIR2 替换保留原压缩方式、偏移及保留字段；新槽采用 32 位 Alpha 与 zlib 压缩。另存对话框会按原包家族选择 `.pak` 或 `.jpk`，不是格式转换。
- 安全另存依赖目标文件系统支持硬链接的独占发布，建议本地 NTFS；不支持时拒绝保存，不降级为可能留下半个文件的复制。
- 保存暂不支持中途取消；不要在保存过程中强制退出。草稿仅在本次进程中，VS Code 强制退出、重启、窗口重载或工作线程崩溃后不提供草稿恢复，请及时另存。
- 若提示“新包已保存，但索引重建失败”，文件已生成；不要把它当作未保存。当前会话不会回退显示旧包缩略图，可在补丁管理重新读取新包。

## 编辑 WIL/WZL 资源组

打开对应数据包并“开启编辑”，无需输入密码。数据文件和同名 WIX/WZX 索引必须齐全且属于已验证的规范布局。操作与 JPK 相同；“另存资源组”对话框输入的是**新的文件夹名称**，不是数据文件名。系统在该目录内保留原数据与索引文件名，一起校验并发布。

Windows 上目标目录必须不存在；出现磁盘错误、校验失败或目录被其他程序提前创建时，不覆盖原包，也不发布半套数据。强制退出可能留下同目录的私有 `.boo-pair-*` 暂存目录，不会自动把它当作可用素材。

## 批量编辑和复制

1. 用 Ctrl/Shift 跨页选择，点击“批量 / 工具”。未选择时可批量导入。
2. 导入可按编号文件名（`123.png`、`Image_000123.png`）、从当前 ID 连续导入或追加。连续导入按文件名自然排序；编号冲突、跳过未存在的 ID、无法保真编码均拒绝整批。
3. 偏移可设绝对 X/Y，也可增减 ΔX/ΔY；空槽保持空槽。清空不会挤动后续 ID。
4. 预检通过后核对“文件名 → ID → 替换/填空/追加”列表，再“应用整批”。取消预检或任何一步失败均不半提交，一次撤销恢复整批。
5. 复制所选图片后，可在本工作台或另一个已开启编辑的工作台粘贴；保留图像及偏移。复制只在本次扩展会话内，不写系统剪贴板。选中空槽时明确拒绝，不悄悄压缩编号。

一批图片最多 256 张，解码后合计不超过 64 MiB；偏移/清空最多 10000 槽。预检/编码阶段可用“取消批任务”，中止检查位于逐图边界；并未承诺所有磁盘/解码环境中都在 1 秒内响应。保存仍不能中途取消。

普通拖动只平移视口；开启编辑且勾选“偏移 / 原点”时，**Alt 拖动**改变当前图片偏移，松开后只提交一步。视口获得焦点时 **Alt + 方向键**移动 1 像素，加 Shift 移动 10 像素。超出坐标范围时拒绝。

## 图像工具与动画

- 镜像保持原画布大小和偏移；最近邻缩放只改变图像尺寸，不改变存储偏移。
- 裁透明边按 Alpha 求边界，并将裁掉的左/上像素补偿到 X/Y，保持显示位置。全透明图不裁；裁后尺寸或颜色不被目标格式支持时拒绝整批。
- 点击“动画”，输入起止 ID（最多 256 帧）。各帧共享原点和画布，空槽保留时长；未知偏移/坏槽不编造位置。可播放、暂停、逐帧查看、调整 1–60 FPS，隐藏页面时暂停。
- “参照图”加载 PNG/BMP，动画面板可调整 X/Y/透明度。参照图仅用于对齐，不写入资源，也不出现在导出的 APNG 中。
- “APNG”导出使用真实 RGBA、固定公共原点、每帧完整替换，保留半透明且无 GIF 调色板损失。画布不超过 4096×4096，全部帧画布的 RGBA 总量不超过 64 MiB。目标必须不存在。
